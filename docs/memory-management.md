# 记忆管理

> 面向第一次接触本项目的人。读完你会明白:AI 是怎么"记住"东西、又怎么在需要时"想起来"的。

## 一句话理解

普通的聊天机器人是"金鱼记忆"——一轮对话结束就忘光。本项目给 AI 装了一套**长期记忆**:
它能把值得记的东西存下来,以后遇到相关问题时自动"想起来",就像人一样。

这套记忆借鉴了人的记忆分类,并且会**自己整理**:零散的经验会被归纳成结论、过时的会被清理、
互相矛盾的会被更新。

## 三类记忆(像人一样)

| 类型 | 通俗说法 | 例子 |
| --- | --- | --- |
| **语义记忆**(semantic) | "我知道的事实" | 用户偏好用中文、用户在准备考研 |
| **情景记忆**(episodic) | "发生过的事" | 上次帮用户整理了一份线性代数笔记 |
| **程序记忆**(procedural) | "学会的做法" | 出这类题时先检索知识库再生成 |

它们最终都存进同一个向量库,只是打了不同的类型标签,用途和整理方式不同。

## 记忆从哪来:两种写入方式

**1. 主动写(明确地记一笔)**

- AI 可以调用 `remember` 工具,把"值得长期记住"的信息写进它自己的私有记忆。
- 用户上传到**知识库**的资料(文档、笔记),也走同一套底层存进向量库。

> 小区分:**知识库**是"用户的资料库"(供出题、grounding);**长期记忆**是"AI 自己记的东西"。
> 两者用同一套技术,但归属不同、互相隔离。

**2. 智能写入(自动从对话里提炼)**

开启后(默认开),每轮对话结束会在**后台**自动做三步——这也是这套记忆最"聪明"的地方:

```
提炼(extract)  →  找相似的老记忆(gather)  →  调和(reconcile)  →  入库
```

- **提炼**:让 LLM 从这轮对话里挑出真正值得长期记的事实(忽略寒暄、一次性内容),并判类型、
  打重要性分。
- **调和**:把新事实和已有的相似记忆比对,决定是——
  - `ADD` 全新信息 → 存进去;
  - `NOOP` 已经记过了 → 不重复存;
  - `REPLACE` 是旧记忆的更新或与之矛盾 → 用新的取代旧的。

这一步保证记忆库不会越灌越多重复、也不会自相矛盾。它跑在后台,**不拖慢回答**。

## 记忆怎么被"想起来":语义检索

记忆不是靠关键词精确匹配,而是靠**语义相似**——把文字变成一串数字向量,找"意思相近"的。
所以问"怎么学好高数",能召回一条写着"用户在准备考研数学"的记忆,哪怕字面不一样。

检索时不止看"像不像",还综合了几个信号,让结果更好用:

- **相关度**:和问题语义有多近(主信号)。
- **新近度**:越近记的稍微加权(可配半衰期)。
- **重要性**:提炼时打的分越高越优先。
- **重排(rerank)**:可选,用更强的模型对候选精排。
- **去冗余(MMR)**:避免召回一堆几乎一样的条目,保证结果多样。

还有几个默认关闭的"召回增强"(需要时开):把问题改写成多条等价查询、生成一段假设答案再检索
(HyDE)、从问题里抽实体精确取。它们能提高召回但每次多花一次 LLM,所以默认不开。

## 记忆会自我整理

记忆不是只进不出,后台会按需维护(`MemoryMaintainer`):

- **整合(consolidation)**:当某个会话攒够了零散的情景记忆,就把**语义相近的一簇**交给 LLM
  蒸馏成**一条**稳定的语义事实,原来那几条标记为"已被取代"。好比把一周的零散笔记归纳成一句结论。
- **过期清理(TTL)**:给不同类型的记忆设保质期(默认永不过期);过期的自动剔除。
- **矛盾与版本**:被取代的旧记忆不物理删除,而是标记 `superseded` 并让新记忆版本号 +1,
  留痕可追溯。

## 记忆在项目里都用在哪

同一套记忆设施,支撑了产品的多个能力:

- **知识库问答 / 出题**:检索用户资料做 grounding、据资料出题。
- **AI 私有长期记忆**:记住用户偏好、目标,后续对话自动带上。
- **长对话不失忆**:超出上下文窗口的更早对话,按当前问题语义召回相关片段带回来
  (详见 [上下文管理](context-management.md) 的 L3 层)。
- **任务经验复盘**:把一次任务的做法与成败记下来(`record_episode`),下次遇到相似任务先
  参考经验(`recall_episodes`)。

## AI 能用的记忆工具

| 工具 | 作用 |
| --- | --- |
| `remember` | 把一段信息写入 AI 的私有长期记忆(`memory:<用户>`) |
| `search_memory` | 检索 AI 自己记下的长期记忆,**不含**用户知识库 |
| `search_knowledge` | 检索用户知识库(上传/保存的资料),作答时可引用的依据 |
| `record_episode` | 记录一次任务的经验(做法/教训与成败) |
| `recall_episodes` | 检索过往相似任务的经验来参考 |

## 存在哪、怎么隔离

- 底层是 **SQLite + sqlite-vec 向量检索**,默认存在 `memory.db`。
- 每条记忆带 `owner_id`(归属谁)和 `kind`(哪类集合),据此隔离:
  用户 A 的知识库(`knowledge:<用户A>`)、AI 对该用户的私有记忆(`memory:<用户A>`)、
  某会话的对话记忆(`conversation:<会话id>`)、任务经验(`episodes`)互不串扰。
- 其中**知识库与私有记忆是两个独立 scope**,对应两个独立工具:`search_knowledge` 只查前者,
  `search_memory` 只查后者。资料引用与 AI 自记的偏好因此不会互相污染,交付门的 grounding
  校验也只认知识库命中(AI 自己记的东西不构成事实依据)。
- 文字入库前会**切块(chunk)**:长文按大小切成若干块分别向量化;表格/代码块在硬上限内尽量整块保留。

## 常用配置

均为 `HARNESS_` 前缀环境变量(见 [`.env.example`](../.env.example)),下表列几个关键项:

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `HARNESS_EMBEDDING_MODEL` | `text-embedding-3-small` | 把文字转成向量的模型 |
| `HARNESS_EMBEDDING_DIMENSION` | `1536` | 向量维度(要和模型匹配) |
| `HARNESS_MEMORY_DB_PATH` | `memory.db` | 向量库文件路径 |
| `HARNESS_MEMORY_WRITE_EXTRACT` | `true` | 是否开启"从对话智能提炼记忆" |
| `HARNESS_MEMORY_WRITE_SAMPLE_RATE` | `1.0` | 智能写入的采样率(1.0=每轮都写) |
| `HARNESS_MEMORY_CONSOLIDATE_AFTER` | `20` | 会话情景记忆攒到这么多条就触发整合;0=关 |
| `HARNESS_TTL_EPISODIC_DAYS` 等 | `0` | 各类型记忆保质期(天);0=永不过期 |
| `HARNESS_SEARCH_TOP_K` | `10` | 检索默认返回条数 |
| `HARNESS_CHUNK_SIZE` / `HARNESS_CHUNK_OVERLAP` | `1000` / `200` | 入库切块大小与重叠 |
| `HARNESS_RERANK_MODEL` | 空 | 配了才启用重排精排;空则不重排 |
| `HARNESS_RETRIEVAL_USE_HYDE` 等 | `false` | 召回增强(多查询/HyDE/实体),默认关 |
