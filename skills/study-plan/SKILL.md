# 学习计划·可执行排期

当用户说「帮我制定 N 天学 X 的计划」「我想系统学 Y，怎么安排」时使用，产出一份**能落地、配好资源**的学习计划，而不是空泛的时间表。

## 步骤

1. **摸清目标与约束**：问清（或 `search_memory` 查）——学什么、目标（考试/入门/项目）、可用时间（每天多久、共几天）、当前水平。
2. **拆知识点**：把目标拆成有依赖顺序的知识点/模块（由易到难、先基础后进阶），估每块所需时间。
3. **排期**：按可用时间把知识点排进日程（如「Day1-2：基础语法；Day3：练习+小测」），每阶段设明确的**产出/检验**（读完某章、做对 N 题）。
4. **配资源**：给每个阶段挂上项目内资源——知识库有资料的标出可检索的主题；`generate_questions`/`add_questions` 预先为各阶段出好配套练习题入库（记下题 id）；缺资料的阶段建议用「联网调研学习」补。
5. **导出计划**：`save_download` 导出一份 Markdown 计划表（日程 + 每日任务 + 检验标准 + 配套题 id），用户可照着执行。
6. **记目标**：`remember` 记下这个学习目标与计划（便于以后「今天该学什么」「进度如何」时对齐）。
7. **收尾**：`unload_skill("study-plan")` 释放上下文，并告诉用户每天可以说「今天学什么」来推进，或用「间隔重复复习」巩固。

## 注意
- 计划要**可落地**：每阶段有具体任务和检验标准，不要只写「学习 X」这种空目标。
- 尽量把资源配齐（题目预先入库、资料标好），让用户拿到就能开学。
- 计划与目标写入 `remember`，方便跨会话跟踪进度、动态调整。
