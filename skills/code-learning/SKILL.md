# 代码·边跑边学

当用户说「教我写 X」「这段代码怎么理解」「帮我调试并讲讲」等编程学习需求时使用。核心是**在沙箱里真跑**，让用户看到结果而非空讲。

## 步骤

1. **定语言与目标**：确认用什么语言（Python/Node/Java）、要学什么（语法点/算法/调试）。可先 `search_memory` 看用户的编程水平。
2. **实跑演示**：写一个**最小可运行**示例，用 `run_python`／`run_node`／`run_java` 在沙箱跑出来，把「代码 + 真实输出」一起给用户，逐行讲原理。别只贴代码不跑。
3. **调试场景**：若用户带了报错代码——先 `run_*` 复现错误，读真实报错，定位根因，讲「为什么错」，改好再 `run_*` 验证通过。
4. **让用户动手**：给一个小改动任务（改参数/补一段逻辑），用户写完后 `run_*` 跑他的版本，跑通就正反馈，跑挂就顺着真实报错引导——不要直接给答案。
5. **讲常见坑**：点出这个知识点上初学者最常踩的 2～3 个错误（结合刚才跑出来的结果）。
6. **沉淀**：`save_download` 把完整可运行代码导出成文件给用户留存；`remember` 记稳定的薄弱点（如「用户对闭包不熟」）；需要的话 `save_to_knowledge` 存讲解笔记。

## 注意
- **必须真跑**：每段示范代码都要在沙箱跑出结果再讲，禁止「我觉得会输出…」。
- 引导优于代劳：用户卡住时先给提示/读报错，别急着贴完整答案。
- 沙箱是一次性的，需要跨步保留的文件用 `write_file`，最终产物给用户用 `save_download`。
